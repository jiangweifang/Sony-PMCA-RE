## 当前目标与审批范围

用户希望先在隔离 QEMU 中运行真实 J1 基线，再评估原生 libJit 入口与中文恢复的完整链路，最后检查重启后中文是否仍正常；不是现在操作真实相机。

已确认的要求：

- 目标环境为**原生 Ubuntu x86_64 桌面**。
- 必须评估原生 libJit 链是否被完整覆盖。覆盖不了就报告阻塞，不能用模拟 root、串口直接执行或桩函数返回成功替代。
- 最低验收按**虚拟相机完整关闭并从同一份实验存储重新启动后，中文仍正常显示**定义。仅重启应用、重新导入字体或重置 seed 不算通过。
- 新 QEMU 方案是交接文档的主计划；旧非 root 探针方案保留为暂停的备选。
- 本轮只做只读资料审查和计划整理。**此次审批仅允许把计划写入项目文档，不包含安装、构建、启动 QEMU、部署 root、修复或任何真实相机操作。**

**当前结论：已有 J1 导入适配，但现成 QEMU 不能直接完成用户要求的端到端验收。** 原生服务链、字体资产和持久化语义存在明确缺口。下面是能力评估、阻塞项与验收规格，不是已经可运行的 root/修复操作手册，也不提供载荷部署步骤。

## 四、分阶段门槛

### A. J1 基线与模型差异审查

后续获准时，先验证纯 J1 输入、两份 seed 一致性及运行资产来源。基线不换成 ALLLANG，不预先强制中文，也不混入机身私有 Backup。

区分“原始 J1 配置”与“QEMU 为运行菜单引入的 IMDB、观察器、虚拟设备和身份数据”。记录默认菜单状态、应用错误、字体访问及退出行为；已有故障不能归因于之后的字体实验。

基线不通过就停止，不为通过而跳过哈希或清单校验。当前状态是尚未取得目标 Ubuntu 的 J1 基线实测。

### B. 原生 libJit 链覆盖评估——当前阻塞

要声称覆盖原生入口，必须有证据串起：虚拟传输边界、原厂服务分派、原 Jiritsu 文件处理、目标文件系统、原加载器以及结果与失败观察。

以下均不能算完整链验证：

- guest 原本就有 root shell，或打印出 `Uid: 0`；
- 用串口直接拷文件、调用加载器或直接调用内部 handler；
- 用 mock、替代服务或写死的返回值模拟成功；
- 绕开禁用的 USB 服务后，仅证明某段普通程序能执行；
- 将上游两台真机的记录当作本地 QEMU 运行结果。

只能逐层标注“源码证据”“部分覆盖”“未覆盖”，缺口未解决时整条链保持 `BLOCKED`。本计划不部署或编写 libJit 载荷，不解除服务过滤，不自动扩展 USB 设备模型或换入口；这些不是为了让测试通过而可以暗中添加的步骤。

### C. 字体与持久卷等价性评估——当前阻塞

先定义字体所在卷、入口工作卷和 Backup 保存位置的映射，核对容量、挂载类型、可写范围及保存机制。当前 tmpfs、每次 seed 重置和 `Backup_save=0` 不符合验收条件。

跨次实验状态必须来自同一组持久化测试镜像；不得在第二次启动时重新从源码目录补字体或覆盖设置。若原内核没有所需虚拟块设备支持，记录设备模型/驱动缺口，不用无限容量内存目录替代 12 MiB 字体卷。

字体资产应作为单独、可追溯的测试输入设计，明确源路径、大小、摘要与预期 guest 路径；不能放宽导入器校验以接受任意运行目录。原始镜像和预设不能被实验副本反向覆盖。

即使以后虚拟 VFAT 的保存验证通过，也只能证明该模型内的保存行为，不能代表实际闪存的断电安全。

### D. 中文恢复对照与实现边界——当前阻塞

完整 root 与修复流程尚无可运行实现，不能把已有 USB 修复事务当作现成载荷。先离线审查其状态读取、备份命令副作用、字体校验、失败处置和接口不兼容点，不运行修复或自动回滚。

下表是未来实验的对照规格，不是本轮创建或修改这些状态的授权：

| 对照 | 目的 | 结论边界 |
| --- | --- | --- |
| 原始 J1 基线 | 确认该环境自身能运行默认菜单 | 不证明中文已开启或 root 可用 |
| 派生缺字体状态 | 分离缺资产、语言状态与模型故障 | 未观察到同类故障不能声称复现了机身重启 |
| 派生修复后状态 | 检查匹配字体被原应用实际加载、中文可读且无新增崩溃 | 必须说明修改来自何种已验证路径；主机预置文件不是 libJit 修复成功 |
| 同一实验存储重启后 | 验证中文与配置的保存 | 新建环境或恢复 seed 无效 |

派生配置仍应保留 J1 的机型/地区背景；不能以更换 ALLLANG 或跨族预设“修复”中文。不将任何实验结果写回真实相机。

### E. 最低重启验收——当前阻塞

只有 B、C、D 的必要条件均被独立验证，才有资格进行用户要求的完整验收：

1. 修复后的虚拟相机实际显示简体中文；记录来自原应用的画面、相关文件摘要、配置状态与错误日志，不能使用主机绘制的覆盖层。
2. 完整结束这一 QEMU 实例并记录退出状态；不是只重启应用、暂停/恢复 CPU 或恢复内存快照。
3. 用同一组实验存储重新启动；禁止重新补字体、重置 Backup、切成 ALLLANG 或从另一份已修复模板启动。
4. 重启后中文仍可读，相关状态未被重新灌入；没有相对于 J1 基线新增的崩溃、循环重启或应用异常。
5. 保存前后文件/配置差异、启动日志、实际显示证据及模型局限。

至少完成一轮完整关闭/重启。字段分别记录 `PASS`、`FAIL`、`BLOCKED`、`NOT_TESTED`，不得把被阻塞或仅模拟的步骤算进通过数量。最终结论只能覆盖已经验证的虚拟环境，不是物理断电、更新后保留或真机安全保证。

## 已确认的约定

- 计划获批后，只实施主机上的源码、测试和文档准备；批准计划不等于批准连接相机。
- 固件版本由用户从机身版本页面人工抄录，不改变设置，记录为“人工提供、未经 USB 验证”。不同于目标 2.01 或无法确认时，不进入本计划的实机阶段。
- 实机输出的仓库外私有目录由用户在实际操作前指定；目录未指定或不可写时，在连接相机前停止。
- 不查询或保存序列号、校准、完整备份、完整分区、无关日志或语言位。
- 不更换或恢复驱动，不格式化存储卡，不挂载/重新挂载机内分区，不自动重试失败命令或做清理写入。
- 允许的服务读取也涉及认证及模式切换；“不发送已知文件/设置写命令”不等于证明固件内部完全没有状态变化或后台写入，不能称为物理零写入保证。

### 本地调查结果

- `tools_chinese_readonly_probe.py` 的默认枚举调用 `get_active_configuration()`，并非仅查看主机设备记录；读取失败后仍可能继续，而且默认读取序列号及语言位，不符合本轮范围。
- `pmca.commands.usb.listDevices()` 会打开候选设备，并可能发送 MSC/PTP 查询，不能作为无设备操作的枚举器。
- `pmca.commands.usb.infoCommand()` 为取得固件版本会初始化 `SonyUpdaterCamera`，本计划禁止调用该命令或复用其版本读取流程。
- `SonySenserAuthDevice.start/stop` 会吞掉部分传输异常；`SonySenserDevice._readAll` 未处理空读停止，响应校验也不能直接满足严格探针要求。
- Windows 现有 `setupapi.py` 可作为主机侧枚举的复用基础，但其错误处理需要在严格路径中显式区分失败和空结果。
- 原始固件参考显示字体目标卷为 nflasha10，容量 12 MiB；这不是相机当前挂载或剩余空间的测量。nflasha6 的 25 MiB 额度不能代替目标卷空间。

当前仓库已有上一轮对 `.github/copilot-instructions.md` 的未提交修改；实现时保留并整合，不回滚、不自动提交或推送。用户附件是只读快照，不编辑。

## 分阶段实施

### 1. 固定查询清单与结果语义

在独立探针内用简单数据结构定义固定目标，不引入新框架、任意路径参数或通用命令入口。

| 查询项 | 当前数据来源 | 必须呈现的状态 |
| --- | --- | --- |
| 相机型号 | 后续获准的单属性读取 `0x003e0005` | 执行前未读取；有效响应后才是实测 |
| 固件版本 | 用户人工抄录 | 人工来源、未经 USB 验证 |
| 简体字体 `/tmp/images/MYingHeiC-GB18030-SJ_wIcon.ltt` | 当前无核准机身读取接口 | 接口不可用；实测大小和摘要为空 |
| 繁体字体 `/tmp/images/MYingHeiC-Big5-SJ_wIcon.ltt` | 当前无核准机身读取接口 | 接口不可用；实测大小和摘要为空 |
| 字体卷挂载、容量与剩余空间 | 当前无核准机身查询接口 | 实测字段为空；离线参考单列 |

每项携带来源与状态；区分未执行、接口不可用、读取失败、人工提供和实测成功。只有未来经核准接口返回有明确语义的不存在结果，才允许标记“文件缺失”。

原始字体参考大小和 SHA-256 复用技术文档，不复制字体文件，不将参考值填进实测字段。整体查询未完成时必须显示“不完整”，不能因为型号读取成功就宣布诊断成功。

### 2. 默认模式仅做主机侧枚举

- 使用 Windows PnP/SetupAPI 的主机记录，复用现有枚举基础；不打开相机 USB 接口。
- 将 USB 后端加载和实例化移入显式读取分支；默认运行、帮助和参数错误都不进入该分支。
- 不调用 `get_active_configuration()`、通用 `listDevices()`、驱动 `openDevice()`、认证或设备查询。
- 只呈现必要的 VID/PID、可取得的驱动服务状态和候选数量，不输出包含序列号的实例路径。
- 仅将 `054C:0E8A` 与 `054C:0336` 作为候选身份，不据此认定型号。无候选、多候选、未知身份或枚举失败均停止，不选“第一个”。
- 驱动信息不可用时报告不可用；不将驱动名当作 USB 可打开或协议兼容的证明，不自动启动驱动安装。

### 3. 严格限制最小服务读取

- 保留显式 `--read` 入口，使用严格参数解析，并在打开设备前要求本轮连接确认，默认拒绝；未知参数不能被忽略，更不能意外触发连接。
- 助手执行前必须逐轮说明并确认认证、可能的模式切换、唯一型号读取、正常退出及失败处置。
- 尽量复用现有认证协议、常量和打包函数。需要修补共用认证/响应处理时，仅增加探针显式启用的严格路径，保留原 GUI/CLI 默认行为。
- 业务请求仅允许 AdjustControl `0x40`、`0x603/1`、型号属性 `0x003e0005`。不读型号编码、序列号、语言位、整份备份、预设备份或 HASP；不提供任意属性 ID 参数。
- 在实际传输出口核验允许的认证/模式控制和业务报文，不能仅凭高层函数名判断只读。USB OUT 的认证/读取请求与文件、设置写命令明确区分。
- 服务模式重枚举只进行有界的主机发现，不重复发送切换/认证命令；目标关联无法确定时停止，不自动换用另一台设备。
- 响应大小、序列、功能号、状态及属性格式必须校验；为接收长度、报文数量和等待设置明确上限。不能把解码替换字符或短包当作有效型号。
- 超时、断连、空读、短包、错序、未知状态或认证错误立即停止。未被证据确认的模式切换异常不得吞掉后继续。
- 正常结束或收到有效但不匹配的型号时，只按已审查的状态执行正常退出；通信状态不明时不再发送退出、重试、其他探测或清理命令，只释放主机资源并报告。
- 不调用 `chinese check/repair/restore`、普通 `tweak`、Updater、旧 `0xFF01` 文件接口、Jiritsu 写入/加载、DEBUG、shell 或外部 Session。

### 4. 离线模拟验收

新增 `tests/test_chinese_readonly_probe.py`，使用项目已有的 `unittest` 与模拟传输，不引入测试依赖或真实 USB 自动发现。

测试必须验证实际请求序列，而不只是返回文案：

- 默认模式、帮助、未知参数、取消/未获确认、输出目录问题都不调用设备打开、认证或 USB 传输。
- 无设备、多设备、未知 PID、驱动查询失败、模式切换后身份无法关联的停止行为。
- 正常业务请求只有一次型号属性读取；不包含序列号、语言位、文件/备份写入、预设备份、Updater、DEBUG 或执行请求。
- 在认证、切换、读取及退出的每个传输位置注入失败，确认不会继续业务探测，也不会进入写入或自动恢复路径。
- 空读、短包、超长包、序列不匹配、功能号不匹配、非成功状态、非法型号和上限边界；覆盖上限值及上限加一。
- 对正常退出与断连退出分别断言，避免无条件 `finally` 再发命令。
- 字体和空间始终保持未验证；模拟值、参考值及人工版本不能出现在实测成功字段中。
- 若改动共用代码，增加默认行为兼容性测试，并执行现有相关中文功能测试；不能沿用此前的测试数量。

实施时先运行专用测试，再按实际改动扩大范围：

```powershell
& 'D:\miniconda3\envs\pmca-a7c2\python.exe' -m unittest discover -s tests -p 'test_chinese_readonly_probe.py' -v
& 'D:\miniconda3\envs\pmca-a7c2\python.exe' -m unittest discover -s tests -p 'test_chinese*.py' -v
git --no-pager diff --check
```

第二条仅在共用代码或相关行为变更时执行。报告实际通过、失败和跳过结果；模拟测试不证明真实 USB 兼容，也不证明分区可访问。环境缺失时先报告，不改 base 或其他环境。

## 实机门槛与阻塞项

### A. 最小型号读取：待单独确认

只有离线审查与测试通过后，才向用户提出一轮明确的最小型号读取请求。执行前确认目标机身、人工版本、候选设备、驱动记录、电源/连接条件及仓库外私有输出目录。

本轮计划审批不会越过这个门槛。若通信或模式退出不确定，停止并向用户报告已到达的状态，不以写入、root、驱动重装或反复操作恢复。

### B. 字体及卷信息：接口阻塞

目前没有符合本计划限制的实机读取接口。本阶段不实现或执行；型号读取成功也不能解除该阻塞。

后续只有出现新的、可独立审查的非执行式读取接口证据，且初始化、正常读取、错误退出均符合边界，再另立适配计划。不能以“字体检查需要”为由自动部署 libJit，也不能靠格式化、测试写入、读取整个分区或路径遍历寻找入口。
